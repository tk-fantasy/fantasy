# 规则列表错配徽标设计

日期：2026-08-17
状态：已确认（用户逐节确认）

## 背景

规则有两个独立维度：`type`（vision / time / weather，决定评估管道）和
`camera_id`（空串=全局，非空=绑定某路摄像头）。两者在 UI 上零联动，
会产生两类错配规则：

1. **全局视觉规则**（type=vision + camera_id=''）：显示在「全局(定时/天气)」
   列表里，但实际对**每一路摄像头**的运动触发都生效。2026-08-17 15:03 与
   15:27 的两次误关灯事故即源于此（「有人比耶关研发部灯」为全局视觉规则，
   任意一路摄像头判定比耶成立即触发）。
2. **摄像头绑定的定时/天气规则**（type=time/weather + camera_id 非空）：
   绑定无意义——非视觉兜底循环评估时不看 camera_id，规则始终全局生效。
   无危害，纯语义误导。

## 目标

错配规则保持可见（不隐藏、不拦截、不改后端），在规则卡片上用徽标+配色
直观提示用户两类错配，引导自行修正绑定或删除。

## 设计

### 检测逻辑

前端 `frontend/src/views/TaskView.vue` 新增 helper：

```js
// 返回 'red' | 'orange' | ''（无标记）
function getMismatch(rule) {
  const type = String(rule.type || 'vision').toLowerCase()  // type 缺失按后端兜底语义视为 vision
  const cam = rule.camera_id || ''
  if (type === 'vision' && !cam) return 'red'
  if ((type === 'time' || type === 'weather') && cam) return 'orange'
  return ''
}
```

### 视觉呈现

| 错配 | 卡片样式 | 徽标文案 |
|---|---|---|
| vision + 全局 | 红色边框 + 浅红背景 | ⚠️ 视觉规则未绑定摄像头 |
| time/weather + 绑定摄像头 | 橙色边框 + 浅橙背景 | 💡 定时/天气规则不依赖摄像头 |

徽标显示在卡片头部行（规则名右侧、摄像头标签附近）。仅徽标，无说明文案。

### 明确不做

- 不改列表过滤逻辑（仍按 camera_id 归属显示，错配规则继续显示——标色
  正是为了让用户看见，而非隐藏）
- 不拦截创建（全局范围仍可创建视觉规则）
- 不改后端 API、评估引擎、规则数据结构
- 不做触发时通知

### 边界情况

- `type` 缺失：后端 `rule_service.py:273-275` 将非法/缺失 type 兜底为
  vision，前端检测保持同一语义（缺 type 视为 vision），与实际评估行为一致。
- 存量规则：加载 `/api/rules` 后逐条检测，违规即标色，无需迁移。

## 测试

前端无单测框架。验证方式：

1. `npm run build`（frontend/）通过。
2. 手动构造四类规则肉眼检查：正常视觉（无标记）、正常定时/天气（无标记）、
   全局视觉（红）、绑定摄像头的定时/天气（橙）。
