# 配置参考

本文档是 `config.json` 和 `.env` 的完整配置 schema 参考，以 `config.example.json` 为准。

---

## 1. config.json 完整 Schema

### 1.1 llm_keys — LLM 密钥定义

数组，每个元素定义一组 API 密钥。

```json
{
  "id": "api-c12091",
  "base_url": "https://open.bigmodel.cn/api/paas/v4",
  "model": "glm-4-flash",
  "type": "chat",
  "chat_path": "/chat/completions",
  "embed_path": "",
  "api_key_env": "ZHIPU_API_KEY_2"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 密钥唯一标识，供 providers 引用 |
| `base_url` | string | 是 | API 基础地址（不含路径） |
| `model` | string | 是 | 模型名称 |
| `type` | string | 是 | `chat` / `vision` / `embed` / `summary` / `stt`（5 种角色） |
| `chat_path` | string | 否 | Chat 接口路径，默认 `/chat/completions` |
| `embed_path` | string | 否 | Embeddings 接口路径，默认 `/embeddings` |
| `api_key_env` | string | 是 | `.env` 中对应的环境变量名 |

> 实际部署中 `llm_keys` 存在数据库 `user_settings` 表（按用户），`config.json` 里的是启动时加载的第一个用户的快照。

### 1.2 providers — 角色→密钥映射

```json
{
  "chat":     { "key_id": "api-c12091", "max_concurrency": 8, "enabled": true, "thinking": false },
  "summary":  { "key_id": "open-f2ef5b", "max_concurrency": 8, "enabled": true, "thinking": false },
  "vision":   { "key_id": "open-fcc2a5", "max_concurrency": 8, "enabled": true, "thinking": false, "multimodal": true },
  "embed":    { "key_id": "api-c12091", "max_concurrency": 8, "enabled": true },
  "stt":      { "key_id": "open-f2ef5b", "max_concurrency": 4, "enabled": true }
}
```

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `key_id` | string | - | 指向 `llm_keys[].id` |
| `max_concurrency` | int | 8 | 该角色最大并发请求数 |
| `enabled` | bool | true | 是否启用 |
| `thinking` | bool | false | 是否启用推理链（深度思考） |
| `multimodal` | bool | true | vision 专用：是否支持多模态图像 |

5 种角色：`chat`（对话）/ `vision`（视觉）/ `summary`（摘要）/ `embed`（嵌入、Emoji 搜索、RAG）/ `stt`（语音转文字）。

### 1.3 vision — 视觉子系统（全局 VLM 编码参数）

> 多摄像头化后，**per-camera 配置（rtsp_url/usb_index/motion_threshold/ptz 等）已迁至数据库 `cameras` 表**，由 `/api/cameras` 管理（详见《05-摄像头视觉/摄像头接入与配置》）。本段只保留全局 VLM 编码 + 采集鲁棒性参数。

```json
{
  "downscale_max_side": 448,
  "jpeg_quality": 70,
  "min_infer_interval_seconds": 3.0,
  "read_retry_count": 3,
  "read_retry_interval_seconds": 0.1,
  "release_cooldown_seconds": 0.8,
  "max_backoff_seconds": 15.0,
  "rtsp_transport": "tcp",
  "offline_hold_seconds": 10
}
```

| 字段 | 默认 | 说明 |
|------|------|------|
| `downscale_max_side` | 448 | VL 输入图像最大边长 (px) |
| `jpeg_quality` | 70（VL 编码）/ 50（MJPEG 预览） | JPEG 编码质量，同键两处读取：VL 推理编码缺省 70，`/video_feed` MJPEG 预览缺省 50 |
| `min_infer_interval_seconds` | 3.0 | 两次推理最小间隔（dhash 节流复用此值） |
| `read_retry_count` | 3 | 读帧失败重试次数 |
| `read_retry_interval_seconds` | 0.1 | 重试间隔 |
| `release_cooldown_seconds` | 0.8 | 摄像头释放冷却 |
| `max_backoff_seconds` | 15.0 | 设备掉线重连退避上限 |
| `rtsp_transport` | tcp | RTSP 传输协议（tcp/udp） |
| `offline_hold_seconds` | 10 | 摄像头离线宽限期（秒）：离线后宽限期内继续补发缓存帧，超时改发 NO SIGNAL 占位帧。宽限期不能默认太短——RTSP 重连一次 open 要 5~21 秒；追求即时反馈可调 3~5 秒 |

> 其余可配项（`infer_timeout_seconds`=45、`slow_read_ms_threshold`=500、`slow_read_reopen_threshold`=3、`backend_blacklist_seconds`=30、`discovery_enabled`=false）代码内有默认值，按需加进 `config.json` 即可。motion 相关参数（`motion_threshold`/`motion_hash_size`/`vision_use_img_count`/`frame_interval_ms` 等）在 `cameras` 表按路配置。

### 1.4 automation — 自动化引擎

```json
{
  "eval_interval_seconds": 10,
  "silent_eval_enabled": true,
  "silent_eval_interval_seconds": 300,
  "nonvision_silent_enabled": true,
  "nonvision_silent_interval_seconds": 30,
  "default_cooldown_seconds": 5,
  "vlm_auto_concurrency": 5
}
```

| 字段 | 默认 | 说明 |
|------|------|------|
| `eval_interval_seconds` | 10.0 | 旧 10s 轮询周期（保留兼容，实际评估由 dhash 事件 + 静默定时器驱动） |
| `silent_eval_enabled` | true | 视觉静默评估开关（无运动时按周期兜底评估） |
| `silent_eval_interval_seconds` | 300 | 视觉静默评估周期（秒），dhash 无运动时最长多久评估一次 |
| `nonvision_silent_enabled` | true | 非视觉静默循环开关（time/weather 规则的周期评估） |
| `nonvision_silent_interval_seconds` | 30 | 非视觉静默循环周期（秒），time/weather 规则的唯一评估来源 |
| `default_cooldown_seconds` | 5 | 规则默认冷却时间 |
| `vlm_auto_concurrency` | 5 | 视觉评估并发上限 |

### 1.5 chat_assistant — 对话助手设定

```json
{
  "persona": "你是Aether，一个本地家庭智能助手...",
  "capabilities": "你能做这些事...",
  "guidelines": "几条原则..."
}
```

| 字段 | 说明 |
|------|------|
| `persona` | 系统人格，可通过 `/api/unique` 修改 |
| `capabilities` | 能力列表（前端只读，空则用内置默认） |
| `guidelines` | 行为准则（前端只读，空则用内置默认） |

> 只有 `persona` 用户可改；`capabilities`/`guidelines` 由系统管理。系统提示组装顺序：persona → guidelines → 时间 → 设备目录 → 控件 → 天气 → 摘要。

### 1.6 rag — 对话检索增强

```json
{
  "recent_turns": 5,
  "retrieve_top_k": 6,
  "retrieve_top_n": 3,
  "soft_max_turns": 12,
  "hard_max_turns": 16,
  "soft_max_tokens": 12000,
  "hard_max_tokens": 16000,
  "soft_max_chars": 24000,
  "hard_max_chars": 32000,
  "summary_blocks": 2
}
```

| 字段 | 默认 | 说明 |
|------|------|------|
| `recent_turns` | 5 | 保留最近 N 轮 |
| `retrieve_top_k` | 6 | 检索候选数 |
| `retrieve_top_n` | 3 | 注入 prompt 的轮数 |
| `soft_max_turns` | 12 | 软限制，触发摘要 |
| `hard_max_turns` | 16 | 硬限制，强制截断 |
| `soft_max_tokens` / `hard_max_tokens` | 12000 / 16000 | token 软/硬限制 |
| `soft_max_chars` / `hard_max_chars` | 24000 / 32000 | 字符软/硬限制 |
| `summary_blocks` | 2 | 摘要分段数 |

### 1.8 ha — Home Assistant

```json
{
  "url": "http://localhost:8123",
  "token": "eyJhbGciOiJIUzI1NiIs..."
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `url` | 是 | HA 地址（无尾部斜杠） |
| `token` | 是 | HA 长期访问令牌 |

> 环境变量 `HA_URL` / `HA_TOKEN` 启动时直接覆盖 `ha.url` / `ha.token`（docker-compose 里就用 `HA_URL: http://homeassistant:8123` 让容器走服务名访问）。没有 `token_env` 之类的间接指向机制——config.json 里存的就是值本身，想用环境变量就设 `HA_TOKEN`。

### 1.9 ptz — 云台（已废弃，兼容保留）

> **多摄像头化后云台配置已迁至 `cameras` 表按路配置**（`ptz_enabled/ptz_ip/ptz_port/ptz_username/ptz_password/ptz_speed/ptz_step_ms`），由 `/cameras` 页面「云台」区块管理。「高级」页的云台速度/步进 UI 也已随旧全局 PTZ 体系移除。首次启动迁移时旧配置段会被搬进第一路摄像头并打上 `cameras_migrated` 标记。此段仅作旧配置兼容读取，新部署请勿手写。

```json
{
  "enabled": false,
  "ip": "",
  "port": 80,
  "username": "",
  "password_env": "",
  "step_ms": 300,
  "speed": 0.5
}
```

> ONVIF via zeep（同步阻塞），后端用 `asyncio.to_thread` 丢线程池。

### 1.16 integration — 集成插件平台

```json
{
  "enabled": true,
  "plugin_dir": "integrations",
  "api_version": "1",
  "startup_timeout": 10,
  "health_check_interval": 30,
  "default_rpc_timeout": 30,
  "max_restarts": 3
}
```

| 字段 | 默认 | 说明 |
|------|------|------|
| `enabled` | true | 集成插件平台总开关 |
| `plugin_dir` | `integrations` | 插件目录（相对 BASE_DIR）；model_adapter 适配器插件也从这里发现 |
| `api_version` | `"1"` | 插件 SDK API 版本 |
| `startup_timeout` | 10 | 插件启动超时（秒），超时按启动失败处理 |
| `health_check_interval` | 30 | 子进程插件健康检查周期（秒） |
| `default_rpc_timeout` | 30 | RPC 调用默认超时（秒） |
| `max_restarts` | 3 | 子进程插件崩溃自动重启上限（超过进入熔断并触发告警） |

> 运行时字段（`broadcast_enabled`/`disabled_plugins`/`current_mode`/`host_configs`）由系统写入，不手工配置。详见《06-集成扩展/模型家族适配插件》与《06-集成扩展/外部MCP Server集成》。

### 1.17 llm — 本地/备用模型适配（model_adapter）

`llm_keys`/`providers` 之外的第二条模型通道：启用后走 OpenAI 兼容接口接本地推理服务（Ollama / LM Studio 等），由 per-user 的 model_adapter 插件链路按家族适配（见《06-集成扩展/模型家族适配插件》）。

```json
{
  "enabled": true,
  "base_url": "http://127.0.0.1:11434",
  "chat_model": "qwen3.5:9b",
  "vision_model": "qwen3.5:9b",
  "embed_model": "qwen3-embedding:0.6b",
  "chat_timeout_seconds": 20,
  "intent_timeout_seconds": 30,
  "vision_timeout_seconds": 30,
  "embed_timeout_seconds": 20,
  "summary_enabled": true,
  "summary_timeout_seconds": 30
}
```

| 字段 | 默认 | 说明 |
|------|------|------|
| `enabled` | true | 本地模型通道开关（可被环境变量 `LLM_ENABLED` 覆盖，`1` 开 `0` 关） |
| `base_url` | `http://127.0.0.1:11434` | OpenAI 兼容服务地址（可被 `LLM_BASE_URL` 覆盖） |
| `chat_model` / `vision_model` / `embed_model` | 见示例 | 各用途模型名（`vision`/`embed` 留空回退 `chat_model`；可被 `LLM_MODEL`/`LLM_EMBED_MODEL` 覆盖） |
| `chat_timeout_seconds` / `intent_timeout_seconds` / `vision_timeout_seconds` / `embed_timeout_seconds` | 20/30/30/20 | 各用途请求超时（秒） |
| `summary_enabled` | true | 摘要是否也走本地通道（关闭则回退 summary 角色） |
| `summary_timeout_seconds` | 30 | 摘要请求超时（秒）；家庭周报的 LLM 总结也读此值 |

## 2. .env 环境变量

```ini
# LLM API 密钥（被 llm_keys[].api_key_env 引用）
ZHIPU_API_KEY_2=...
LLM_KEY_API_C12091=...
LLM_KEY_OPEN_F2EF5B=...
LLM_KEY_OPEN_FCC2A5=...

# JWT 鉴权
JWT_SECRET=...                # 不设则自动生成并存 app/data/.jwt_secret

# 可选：API 兜底令牌（JWT 之外的 X-API-Token 认证，留空不启用）
APP_TOKEN=

# 日志级别（覆盖 config.json logging.level）
LOG_LEVEL=INFO

# HA / 本地模型 / MQTT / 摄像头云台 / STT / 飞书插件等
HA_URL=...                    # 覆盖 config.json ha.url（Docker 部署由 compose 注入服务名）
HA_TOKEN=...                  # 覆盖 config.json ha.token
LLM_ENABLED=1                 # 覆盖 llm.enabled（1 开 0 关）
LLM_BASE_URL=...              # 覆盖 llm.base_url
LLM_MODEL=...                 # 覆盖 llm.chat_model / vision_model
LLM_EMBED_MODEL=...           # 覆盖 llm.embed_model
MQTT_USER=aether              # mosquitto / simulator 凭证（改了需删 mosquitto/config/passwd 重启）
MQTT_PASSWORD=aether
RTSP_PASSWORD=...             # 旧版单摄 RTSP 密码（多路摄像头密码存数据库，摄像头设置页配置）
PTZ_PASSWORD=...              # 云台 ONVIF 密码
SILICONFLOW_STT_KEY=...
FEISHU_APP_ID=...             # 飞书机器人插件（integrations/feishu）
FEISHU_APP_SECRET=...
FEISHU_VERIFICATION_TOKEN=...
```

| 变量 | 说明 |
|------|------|
| `*_API_KEY` / `LLM_KEY_*` | LLM 提供商密钥，被 `api_key_env` 引用 |
| `JWT_SECRET` | JWT 签名密钥；不设则持久化到 `app/data/.jwt_secret`，再没有则每次启动随机（重启失效） |
| `APP_TOKEN` | 兜底令牌，配 `X-API-Token` 头使用 |
| `LOG_LEVEL` | 日志级别 |
| `HA_URL` / `HA_TOKEN` | 启动时直接覆盖 `ha.url` / `ha.token` |
| `LLM_ENABLED` / `LLM_BASE_URL` / `LLM_MODEL` / `LLM_EMBED_MODEL` | 覆盖 `llm` 段对应项（启动时生效一次） |
| `MQTT_USER` / `MQTT_PASSWORD` | mosquitto 与虚拟设备模拟器的凭证（默认 `aether`/`aether`） |
| `RTSP_PASSWORD` / `PTZ_PASSWORD` | 旧版单摄 RTSP / 云台 ONVIF 密码 |
| `SILICONFLOW_STT_KEY` | 语音转文字密钥 |
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` / `FEISHU_VERIFICATION_TOKEN` | 飞书机器人插件凭证 |

> 环境变量优先级高于 `config.json`。LLM Key 的值在 `.env`，名字在 `config.json` 的 `api_key_env`，两层间接。

## 3. docker-compose.yml

共 **5 个服务定义**，其中 `ollama`（profile `local-llm`）与 `simulator`（profile `simulator`）**默认不启动**，按需 `docker compose --profile <名> up -d <服务>` 启用：

```yaml
services:
  mqtt:
    container_name: mosquitto
    image: eclipse-mosquitto:2
    ports:
      - "127.0.0.1:1884:1884"    # 只绑宿主回环；凭据从 .env 注入（MQTT_USER/MQTT_PASSWORD）
    volumes:
      - ./mosquitto/config:/mosquitto/config
      - ./mosquitto/init.sh:/mosquitto/init.sh:ro
    entrypoint: ["/bin/sh", "/mosquitto/init.sh"]   # 首次启动自动生成 passwd
    healthcheck: …              # QoS1 发布探活（收到 PUBACK 才算健康）

  homeassistant:
    container_name: aether-ha
    image: homeassistant/home-assistant:stable     # 官方镜像；ghcr.io 国内常超时，改用 Docker Hub 同步镜像
    ports:
      - "8123:8123"
    volumes:
      - ./ha_config:/config
    depends_on:
      mqtt: { condition: service_healthy }
    restart: unless-stopped

  aether:
    container_name: aether
    build: .
    image: aether-app:latest
    ports:
      - "8010:8010"   # 主服务（API + WebSocket + 前端 SPA）
      - "8011:8011"   # 冷启动进度端口
    env_file: .env
    environment:
      HA_URL: http://homeassistant:8123   # 容器内用服务名访问 HA
    volumes:
      - ./config.json:/aether/config.json
      - /var/run/docker.sock:/var/run/docker.sock   # 「虚拟设备」开关启停容器用（可选，可删）
      - aether-data:/aether/app/data       # SQLite / JWT / emoji 索引（named volume，Windows bind mount 不支持 SQLite WAL）
      - ./logs:/aether/logs
      - ./backups:/aether/backups
      - ./app/sg/output:/aether/app/sg/output
    healthcheck: …              # /healthz 存活探针（事件循环卡死时自动重启）
    mem_limit: 2g               # 防 opencv+faiss+langgraph 失控拖垮宿主

  ollama:                       # profile: local-llm，纯内网本地模型（可选）
    container_name: aether-ollama
    image: ollama/ollama:latest
    profiles: ["local-llm"]

  simulator:                    # profile: simulator，虚拟设备模拟器（默认不启动）
    container_name: aether-simulator
    image: python:3.11-slim
    profiles: ["simulator"]
    volumes:
      - ./ha_config/ha_simulator.py:/sim/ha_simulator.py:ro
```

| 容器名 | 镜像 | 端口 | 挂载 | 启用方式 |
|--------|------|------|------|---------|
| `mosquitto` | `eclipse-mosquitto:2` | 127.0.0.1:1884 | `./mosquitto/config`、`init.sh` | 默认启动 |
| `aether-ha` | `homeassistant/home-assistant:stable` | 8123 | `./ha_config` | 默认启动 |
| `aether` | 本地构建 / `aether-app:latest` | 8010 / 8011 | `./config.json`、named volume `aether-data`、`./logs`、`./backups`、sg output | 默认启动 |
| `aether-ollama` | `ollama/ollama:latest` | —（容器网络） | named volume `ollama` | `--profile local-llm` |
| `aether-simulator` | `python:3.11-slim` | — | `ha_config/ha_simulator.py`（只读） | `--profile simulator`，之后用「高级配置 → 虚拟设备」开关随时启停 |

### Mosquitto 配置 (`mosquitto/config/mosquitto.conf`)

```conf
listener 1884
allow_anonymous false
password_file /mosquitto/config/passwd
```

> HA 镜像 `homeassistant/home-assistant:stable`（官方镜像的 Docker Hub 同步版，ghcr.io 国内拉取常超时），配置通过 `./ha_config` 挂载，只用了 `default_config` + 内置 MQTT 集成，无需手动构建。Mosquitto 关了匿名访问，`init.sh` 首次启动自动生成 `passwd`（凭证来自 `.env` 的 `MQTT_USER`/`MQTT_PASSWORD`，默认 `aether`/`aether`）。1884 只绑定宿主回环——HA/模拟器走 docker 内部网络访问 broker，外部设备确需访问时自行放开并务必设强 `MQTT_PASSWORD`。模拟器 `ha_simulator.py` 通过 MQTT 上报虚拟设备状态（10 个演示设备），需要时用 `--profile simulator` 启用，接真实设备可不启动。
