# 设备语义映射 — 让 AI 的直觉和设备的真实动作对得上

有些设备的"开关"是**反的**：继电器 `turn_on` 物理上是关门、`turn_off` 是开门；有些窗帘的 `open_cover` 其实装反了方向。以前你只能靠写**备注**提醒 AI"这个开关是反的"，但 AI 偶尔还是会按字面理解。

**语义映射**把这个问题从"提示 AI"变成"代码级纠正"：AI 照常凭直觉调 `turn_on`，系统在执行前**无条件**把它替换成设备真正的动作，AI 看到的状态也同步翻转——它根本不需要知道设备是反的。

---

## 一、它和备注（entity_note）的区别

| | 备注 | 语义映射 |
|---|------|---------|
| 层面 | 提示词层（告诉 AI 注意） | 执行层（代码强制替换 service） |
| 可靠性 | 依赖模型理解，偶尔失效 | 100% 生效，模型无法绕过 |
| 状态反馈 | 原样返回物理值 | 对称翻转对的 state 自动反转，AI 不说反话 |
| 适合 | 描述性信息（"这个插座管鱼缸"） | **动作反向/错位**这类硬规则 |

---

## 二、在哪配

聊天框打 `/semantics` 进入「语义映射」页（侧边栏无入口）。

页面两层结构：

1. **一级：选实体**。页面列出全部实体（可搜索），点选一个进入二级；已配置映射的实体会显示在顶部卡片列表里，方便直接改。
2. **二级：配服务映射**。展示该实体所属域的可用服务列表，对每个服务指定「映射到哪个服务」+ 一句描述。

### 典型配置：反向继电器

实体的 `turn_on` 实际是关门、`turn_off` 实际是开门，配成**对称翻转对**：

| 源服务（AI 直觉） | 映射目标（真实动作） | 描述（AI 事后看到） |
|------------------|---------------------|---------------------|
| `turn_on` | `turn_off` | 继电器反向：开=关门 |
| `turn_off` | `turn_on` | 继电器反向：关=开门 |

保存时系统校验：目标服务必须属于该实体的域、且不能和源服务相同。配错了会直接报错拒绝。

---

## 三、执行时发生了什么

以反向继电器为例，你对 AI 说"打开大门"：

```
AI 调 call_service(turn_on)          ← AI 凭直觉，永远按正常语义调
        │
        ▼
语义映射过滤层（无条件替换）
        turn_on → turn_off           ← 不判断意图，直接替换
        │
        ▼
真实执行 turn_off（物理开门）
        │
        ▼
state 隐含翻转：off → on             ← 对称翻转对自动反转
        │
        ▼
结果反馈给 AI：
  "已 turn_on（实际执行：继电器反向：开门）"
  state = on                          ← AI 看到的与它的操作方向一致
```

三个关键设计：

- **无条件替换**：不做意图判断（判断就可能错，错上加错）。AI 永远按正常语义调用，过滤器永远纠正。
- **映射规则不进提示词**：AI 不知道映射存在，避免"模型自作聪明绕过"或双重反转。
- **state 同步翻转**：`get_entities`、`get_device_manual`、设备目录、`call_service` 返回的 on/off 全部反转。AI 看到门是"开"就去关（调 turn_on→真实 turn_off 物理关门），方向永远一致。

> **批量控制的共识制**：一条指令操作多个实体时（"把三个开关都打开"），只有**全部实体**对同一服务映射到相同目标才替换；混合设备场景下按单实体映射替换会误伤未映射的设备，此时不替换。

---

## 四、删掉映射

把实体的映射清空（mappings 置空）保存即删除，设备回到"AI 调什么就执行什么"的原生行为。顶部已配置卡片里也可以直接管理。

---

## 五、接口与存储

| 操作 | 接口 |
|------|------|
| 查全部映射 | `GET /api/ha/action-maps` |
| 设置/更新一个实体 | `PUT /api/ha/action-maps`（空 mappings=删除） |
| 查各域可用服务 | `GET /api/ha/entity-services` |

存储在数据库 `emoji_preferences` 表（scope=`entity_action_map`），JSON 结构：

```json
{ "switch.door_relay": { "mappings": {
    "turn_on":  { "target": "turn_off", "description": "继电器反向：开=关门" },
    "turn_off": { "target": "turn_on",  "description": "继电器反向：关=开门" }
} } }
```

保存后立即清缓存并刷新设备目录，不用等 60 秒周期、不用重启。

## 常见问题

**Q：只映射一个方向行不行（比如只有 turn_on→turn_off）？**
A：可以，但那就不是"对称翻转对"，state 不会自动反转——AI 看到的状态是物理原始值。反向设备建议成对配置。

**Q：AI 会不会在聊天里说出"实际执行了 turn_off"？**
A：结果反馈里带映射描述，AI 汇报时会自然地解释（"已为你打开大门"），不会让用户困惑。

**Q：和「AI 可操作」权限冲突吗？**
A：不冲突，先查权限再走映射。被标为禁止 AI 操作的实体根本到不了映射这一步，见《AI设备操作权限》。
