# 场景模式——一键把一组设备切到预设状态

「回家」「观影」「睡眠」这类需求，本质是把**一组设备**一次性切到预设状态。场景模式就是干这个的：把当前设备状态拍下来存成一个场景，之后点一下（或跟 AI 说一句）就能整体还原。

场景是**全家共享**的：任何家庭成员都能创建、应用、删除，和设备面板的其他功能权限一致。

---

## 一、入口在哪

- **设备页顶部**：`/halist` 页面最上方有一条「🏠 场景模式」横条，已保存的场景以胶囊芯片排列，点芯片即应用。
- **聊天**：直接跟 AI 说「打开观影模式」「把现在的灯光存成观影模式」，AI 会调场景工具完成（见第四节）。

---

## 二、创建场景——两种方式

### 方式 1：面板上「保存当前状态」（推荐）

1. 在设备面板把设备调到你想要的状态（灯的亮度、空调温度、窗帘开度……）。
2. 在场景条右侧输入框填个名字，比如「观影模式」。
3. 点「+ 保存当前状态」，系统把**当前所有可控设备的状态**拍下来存成场景。

「捕获当前状态」覆盖这些设备类型（其余类型跳过不捕获）：

| 设备类型 | 捕获内容 |
|---------|---------|
| 灯（light） | 开/关，开灯时保留亮度和色温 |
| 开关（switch） | 开/关 |
| 窗帘（cover） | 开度百分比（关闭则记为关） |
| 风扇（fan） | 开/关 |
| 空调（climate） | 开/关，开机时保留目标温度 |
| 加湿器（humidifier） | 开/关 |

### 方式 2：让 AI 创建

跟 AI 说「把客厅灯调到 50%、窗帘关上，存成观影模式」，AI 会逐条控制设备后用 `scene_create` 把这组动作存下来。你也可以只说动作清单，让 AI 直接生成场景而不实际执行。

---

## 三、应用场景

- **面板**：点场景芯片。系统**逐条**调用 Home Assistant 执行场景里的动作，单条失败不会中断其余设备，结束后提示结果——全部成功显示「✅ 已应用」，部分失败显示「⚠️ N/M 个设备成功」，失败的设备会列出来。
- **聊天**：说「观影模式」「该睡觉了，切睡眠模式」，AI 调 `scene_apply` 应用，并告诉你成功几个。

> 场景应用是「按记忆重放」：它把设备切到**保存那一刻**的状态，不感知当前实际状态（比如保存时窗帘开 50%，应用时就会开到 50%）。

---

## 四、在聊天里管理场景

AI 内置了三个场景工具，自然语言即可驱动：

| 你说 | AI 做什么 |
|------|----------|
| 「现在有哪些场景？」 | 调 `scene_list` 列出场景名和动作数 |
| 「打开回家模式」 | 调 `scene_apply` 应用场景 |
| 「把现在的状态存成睡眠模式」 | 调 `scene_create`（capture 捕获方式） |

> 注意区分：只想「开个灯」时 AI 会直接控设备，不会建场景；只有你明确要「存成模式/保存为场景」时才会创建。

---

## 五、删除场景

面板上点场景芯片右侧的「×」，确认后删除。目前面板和 REST 都能删，聊天里暂不支持删除。

---

## 六、进阶：REST API

场景数据存在本地 SQLite 的 `scenes` 表里，也可通过 REST 直接管理（登录后调用）：

| 端点 | 说明 |
|------|------|
| `GET /api/scenes` | 列出所有场景 |
| `POST /api/scenes` | 创建/更新场景。`{"name": "观影", "capture": true}` 从当前状态捕获；或传 `actions` 动作列表；带 `"id"` 则覆盖更新同 ID 场景 |
| `POST /api/scenes/{id}/apply` | 应用场景，返回 `{total, ok, results}` 逐条结果 |
| `DELETE /api/scenes/{id}` | 删除场景 |

`actions` 的格式与 HA 服务调用一致：

```json
[
  {"domain": "light", "service": "turn_on", "entity_id": "light.ke_ting", "data": {"brightness": 200}},
  {"domain": "cover", "service": "close_cover", "entity_id": "cover.ke_ting", "data": {}}
]
```

创建时系统会对 actions 做白名单清洗（只保留 `domain`/`service`/`entity_id`/`data` 四个字段、实体 ID 必须带 `.`），空场景（没有动作）会被拒绝。

## 七、常见问题

**Q：捕获的场景没包含某个设备？**
捕获只覆盖上表六类设备，且只记「能推导成动作」的状态。传感器、音响等不在捕获范围；可以用 AI 创建方式（方式 2）手工指定动作。

**Q：改了设备（换名、删了设备）后场景会失效吗？**
场景按 `entity_id` 记录动作。被删设备的动作应用时会失败，但不影响场景里其他设备，结果里会标出失败项。在 HA 里改名不影响（entity_id 不变即可）。

**Q：场景和自动化规则有什么区别？**
场景是**手动触发**的静态状态快照；自动化规则是**条件触发**的动态逻辑（时间/状态/视觉），详见[自动化规则创建指南](../04-自动化规则/自动化规则创建指南.md)。
