# 摄像头接入与配置

Aether 支持接入**多路摄像头**（RTSP 网络摄像头 + USB 本地摄像头混用），把画面交给视觉大模型（VL）理解。这一篇讲怎么把摄像头接进来、参数怎么调、面板怎么用。

## 一、它整体怎么工作

```
摄像头 ──抓帧──▶ 运动检测(dHash) ──有变化──▶ 视觉模型(VL) ──▶ 识别结果
                                          │
                                          ├─▶ 摄像头面板显示（/camera）
                                          └─▶ 触发自动化规则评估
```

三个关键设计，先记住，后面会展开：

- **运动门控**：不是每一帧都调 VL（贵且慢），而是先用一个极轻量的 dHash 比对，画面没动就跳过。只有检测到运动才触发推理。
- **关注项按摄像头分**：你可以给每一路摄像头分别告诉模型「重点看什么」（比如「猫有没有上沙发」）。详见《视觉关注项配置》。
- **AI 预览单路**：所有摄像头都可以同时「启用采集」（后台抓帧 + 运动检测 + 自动化），但**同一时刻只有一路**开着 AI 预览（`display_enabled`），聊天里 `/camera` 看到的就是这一路。

## 二、在「摄像头管理」页接入

所有摄像头都在**「摄像头管理」页（`/cameras`）**里维护（侧边栏「摄像头」或聊天框打 `/cameras`），不再需要手改 `config.json` 的 `vision` 段。

页面顶部显示「N 路摄像头 · AI 预览同一时刻仅 1 路」，右上角「+ 添加摄像头」新增。

### 1. 添加摄像头

点击「+ 添加摄像头」打开编辑弹窗，分几段填：

**基本信息**

| 字段 | 说明 |
|------|------|
| 名称 | 如「客厅」「门口」，用于识别和 AI 描述 |
| 区域 | 归属哪个房间（从 HA 的区域列表选，可留空「未分配」） |
| 来源 | `RTSP 网络摄像头` 或 `USB 本地摄像头` |
| 启用采集 | 勾选后这路摄像头开始后台抓帧 + 运动检测 + 自动化评估 |
| AI 预览 | 勾选后这路成为当前 AI 预览路（同路切换，开新的会自动停旧的） |

**RTSP 配置**（来源选 RTSP 时显示）

| 字段 | 说明 |
|------|------|
| RTSP 地址 | 完整地址，如 `rtsp://192.168.1.100:554/stream` |
| 用户名 | 摄像头登录用户名（无鉴权留空） |
| 密码 | 摄像头密码（编辑时留空表示不修改） |
| 试连 | 填完点「试连」验证连通性，返回 ✅/❌ |

**USB 配置**（来源选 USB 时显示）

| 字段 | 说明 |
|------|------|
| 设备序号 | USB 设备号，`0` 通常是第一个摄像头；笔记本自带的一般也是 `0`，有多个依次试 `1`、`2` |

> 后端连接 RTSP 时把 `rtsp://host/path` 拼成 `rtsp://user:pwd@host/path`，用 `cv2.CAP_FFMPEG` 打开。没配凭证则裸连（支持无鉴权摄像头）。密码会加密处理，不落 `config.json` 明文。

**云台（PTZ）** — 支持 ONVIF 协议的可转摄像头

| 字段 | 说明 |
|------|------|
| 启用云台 | 勾选后该路在 `/camera` 面板显示方向键 |
| IP | 摄像头 IP（与 RTSP 地址同一台设备的 IP） |
| 端口 | ONVIF 端口，默认 80 |
| 用户名 / 密码 | ONVIF 登录凭证（编辑时密码留空不改） |

**视觉关注项** — 见《视觉关注项配置》，仅编辑已有摄像头时显示。

### 2. 摄像头卡片

每路摄像头一张卡片：

- 名称、区域（📍）、MAC（如果已捕获）、来源（RTSP 地址 / `USB #N`）。
- 右上角徽标：`AI 预览`（当前预览路）或 `休眠`。
- 三个操作：**启用**（采集）开关、**预览**（AI 预览）开关、**配置**、**删除**。
- 启停都即时生效；预览切换同路互斥，切到新的会自动停旧的。

### 3. ONVIF 自动发现（找回掉线的摄像头）

摄像头 DHCP 换 IP 后 RTSP 会断，卡片「配置」弹窗里有两个自救手段：

| 操作 | 说明 |
|------|------|
| **发现设备** | 按已记录的 MAC/凭证扫描子网，找到后自动更新 `ptz_ip` 和 RTSP 地址的 host |
| **手动设 IP** | 知道新 IP 时直接填，立即生效 |

后端也会在 worker 连续开流失败时自动触发一次发现找回 IP（指数退避兜底）。掉线期间的详细机制见《运动检测与视觉推理》。

## 三、视觉参数：每路优先，全局兜底

**每路摄像头的运动阈值、推理间隔等参数存在 `cameras` 表**（per-camera，新建时写入默认值，互不影响）。编辑弹窗暂未开放这些输入，调整走接口 `PUT /api/cameras/{id}`（body 里带上要改的字段，保存即重建该路，即时生效）：

| 参数 | 默认 | 说明 |
|------|------|------|
| 运动检测阈值 `motion_threshold` | `15` | 画面变化多大算「有动静」（1~256，dHash Hamming 距离）。**调大 = 更迟钝，调小 = 更灵敏**；拉到 256 = 关掉 dhash 触发，降级为纯定时器 |
| 推理最小间隔 `vision_min_infer_interval` | `8.0` | 两次推理之间的最小间隔（秒） |
| 空闲兜底 `vision_max_idle_interval` | `120.0` | 画面静止时最长多久强制推理一次（秒） |
| 帧采样 `vision_use_img_count` / `frame_interval_ms` | `3` / `2000` | 单次推理送几帧、抓帧间隔 |

「高级配置」页（`/advanced`）的「**摄像头参数**」弹窗保留的是**全局旧入口**（写 `config.json` 的 `vision`/`ptz` 段，兼容老配置路径；多摄像头下按路字段优先，全局值只作用于旧单摄路径）：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 运动检测阈值 `motion_threshold` | `15` | 全局旧值 |
| 推理最小间隔 `min_infer_interval_seconds` | `3.0` | 全局值（自动化评估的触发节流间隔 `min_trigger_interval` 在单摄与多路路径都复用这个值） |
| 云台转动速度 `ptz.speed` | `0.5` | 旧单摄云台速度 |
| 云台步进时长 `ptz.step_ms` | `300` | 旧单摄云台步进 |

同页「**自动化**」弹窗里与视觉强相关的全局项：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| dhash 阈值滑块 | `15` | 与全局 `vision.motion_threshold` 同一个值（`POST /api/automation/dhash-threshold`），两条 UI 入口写同一个配置 |

其余视觉编码参数（`downscale_max_side`、`jpeg_quality`、`read_retry_count`、`release_cooldown_seconds`、`max_backoff_seconds`、`rtsp_transport` 等）仍在 `config.json` 的 `vision` 段，代码里有默认值，一般不需要动：

```json
"vision": {
  "downscale_max_side": 448,
  "jpeg_quality": 70,
  "min_infer_interval_seconds": 3.0,
  "read_retry_count": 3,
  "read_retry_interval_seconds": 0.1,
  "release_cooldown_seconds": 0.8,
  "max_backoff_seconds": 15.0,
  "rtsp_transport": "tcp"
}
```

> 旧版的 `camera_index` / `rtsp_url` / `rtsp_username` / `rtsp_password_env` / `ptz.*` 等 per-camera 配置已全部迁到 `/cameras` 页的摄像头记录（数据库 `cameras` 表），不再从 `config.json` 读。老部署首次启动时会把旧 `vision`/`ptz` 段自动迁移成一行默认摄像头，无需手动改。

### 常见调整场景

- **太灵敏，没人也一直触发** → 调大运动检测阈值（如 `20`、`25`）。
- **有人进来却没反应** → 调小运动检测阈值（如 `10`），或检查 `downscale_max_side` 是否太小导致人影糊掉。
- **想省 token / 模型慢** → 调大 `vision_min_infer_interval`，或把 `vision_use_img_count` 改成 `1`（以上都是每路字段，走 `PUT /api/cameras/{id}`）。
- **夜间灯光闪烁误触发** → 调大运动检测阈值。

## 四、摄像头面板（/camera）

在聊天框输入 `/camera` 打开摄像头预览浮层（预览的是当前 `display_enabled` 的那一路）。面板从上到下是：

1. **视频预览**：实时 MJPEG 画面。右上角徽标显示 `已连接` / `等待连接`。
2. **状态条**：画面断了会显示「设备重连中」并提供「重试」按钮；重连中也可以直接「关闭预览」。前端最多重连 10 次（指数退避，约 5 分钟），期间只要设备恢复就自动接回。
3. **云台方向键**（仅该路 `ptz.enabled` 时显示）：点一下转一小段（约 300ms）后自动停。
4. **统计区**：
   - `运动距离`：当前 dHash 距离，超过 `motion_threshold` 才触发推理。
   - `推理次数`：累计调用 VL 的次数。
   - `模型 FPS`：推理频率上限（≈ `1 / min_infer_interval`）。
5. **识别反馈**：模型当前对画面的描述，比如「沙发上有人」。

> 面板里的「正在确认…」是显示层平滑：连续几帧都看到事件才正式显示结论，避免单帧误判闪一下。这只是给看的，不影响自动化规则触发（规则直接用模型判断结果，不走这个平滑）。详见《运动检测与视觉推理》。

## 五、相关接口

多摄像头统一走 `/api/cameras/*`，聊天面板兼容旧入口：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/cameras` | GET/POST | 列出 / 新增摄像头 |
| `/api/cameras/{id}` | PUT/DELETE | 更新 / 删除 |
| `/api/cameras/{id}/video_feed` | GET | 该路 MJPEG 视频流（需 JWT） |
| `/api/cameras/{id}/state` | GET | 该路状态（帧率、运动距离、反馈等） |
| `/api/cameras/{id}/display/enable`·`disable` | POST | AI 预览路切换（互斥） |
| `/api/cameras/{id}/test-stream` | POST | RTSP 试连 |
| `/api/cameras/{id}/ptz/move`·`stop`·`step` | POST | 云台控制（按/点） |
| `/api/cameras/{id}/discovery/find`·`manual-ip` | POST | ONVIF 发现 / 手动设 IP |
| `/api/cameras/{id}/focuses` | GET/POST | 该路关注项（详见《视觉关注项配置》） |
| `/api/video_feed` | GET | 旧版主摄像头 MJPEG 流（兼容） |
| `/api/state` | GET | 旧版全局状态 = 主摄像头状态（兼容） |

## 六、不开视觉模型会怎样

如果没配置 `vision` 角色的 LLM Key（见《LLM模型角色配置》），视觉模型处于「未启用」状态。这时：

- 摄像头照常抓帧、面板照常显示画面。
- 但不会有识别结果，面板反馈显示「视觉模型未启用，当前只有摄像头画面，没有识别。」
- 自动化里的「视觉触发规则」退化为纯上下文规则（只看时间/天气，不看画面）。

所以要完整使用视觉能力，务必配好 `vision` 角色的 Key。

## 七、排查

| 现象 | 排查方向 |
|------|----------|
| 某路面板一直「等待连接」 | `/cameras` 页「试连」验证；USB：确认设备序号、是否被别的程序占用、看后端日志有无读帧报错；RTSP：确认地址能通（VLC 试播）、用户名密码对不对、摄像头是否开了 RTSP 服务 |
| 画面有但从不识别 | 确认 `vision` 角色 Key 已配；看 `motion_threshold` 是否过高；确认画面确实有运动 |
| 识别太频繁/太慢 | 调 `min_infer_interval_seconds` 和 `motion_threshold` |
| PTZ 方向键不显示 | 确认该路「启用云台」勾选、IP/端口/凭证填对 |
| 设备掉线后不恢复 | RTSP 网络抖动会自动指数退避重连；连续失败会触发 ONVIF 发现找回 IP；还不行就在 `/cameras` 页手动「发现设备」或「手动设 IP」 |
| USB 画面卡顿后自愈 | 后端有慢读检测：连续 3 次读帧超 500ms 会自动重开设备并临时拉黑该 backend 30 秒 |
