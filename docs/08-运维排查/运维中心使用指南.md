# 运维中心使用指南

> 对应页面：`/operations`（聊天输入 `/operations` 跳转，**仅管理员可见**）
> 权限要求：管理员（首个注册用户）

运维中心把运维能力全部按钮化，无需 SSH 登录主机操作文件。页面分五个模块：

- **系统体检**：一键部署体检（端口/网络/资源/RTSP）
- **诊断包导出**：打包脱敏诊断信息，远程排障用
- **备份与恢复**：创建、恢复、删除备份
- **版本与升级**：查看版本与升级历史；升级包自动升级（投放即升）
- **升级包分发**：发布方一键导出升级包（微信/网盘发给对方）；接收方投放后自动升级
- **操作审计**：查看最近运维操作记录

## 2. 诊断包导出

点击「导出诊断包」按钮，自动打包以下内容：

| 内容 | 说明 |
|------|------|
| `config.json` | 脱敏后的配置（密钥字段打码） |
| 系统信息 | uname、docker ps、磁盘/内存使用 |
| 日志文件 | 最近日志（每文件尾部 2MB，总量 10MB） |

**用途**：远程排障时，将诊断包发给技术支持，无需登录主机查看日志。

**安全说明**：
- 密钥字段自动脱敏（显示为 `***...***`）
- 设备 MAC 地址占位处理
- 日志中可能包含设备名、IP 等信息，导出前请确认可分享

## 3. 部署体检

点击「运行体检」按钮，自动检查以下项目：

| 检查项 | 说明 | 通过条件 |
|--------|------|----------|
| 端口占用 | 8010、8123、1884 | 端口未被其他进程占用 |
| HA 连通性 | Home Assistant 地址可达 | HTTP 响应正常 |
| RTSP 连通性 | 摄像头 RTSP 流可达 | cv2.VideoCapture 成功 |
| DNS 解析 | DNS 服务正常 | 可解析域名 |
| 磁盘空间 | 磁盘剩余空间 | > 2GB |
| 内存空间 | 内存剩余空间 | > 2GB |
| NTP 同步 | 时间同步状态 | systemd-timesyncd 正常 |

**体检报告**：每项显示"通过/警告/失败 + 修复建议"，平均 < 10 秒完成。

## 4. 版本与升级

### 4.1 查看版本

显示当前版本号、Docker socket 状态、升级历史。

### 4.2 升级包自动升级（投放即升，推荐）

把升级包放进指定文件夹，系统自动完成升级，全程无需登录页面：

1. 拿到升级包 `aether-update-<版本>.tar.gz`（发布方经运维页「升级包分发」导出，见 4.3）
2. 放到服务器 `Aether/backups/` 目录（与备份文件同目录）
3. 等约 1 分钟（文件拷完落稳后）——系统自动：校验 sha256 与版本兼容 → 导入镜像 → 重启生效 → 删除安装包

规则与保护：

- **只升不降**：版本高于当前才自动安装；相同/更低版本不自动动（可在 4.3 的列表里手动安装，用于重装/回退）
- **失败隔离**：安装失败的包改名为 `<原名>.failed` 不再重试，人工排障后去掉后缀可重新触发
- **落稳判定**：文件放入后 60 秒内无改动才视为拷贝完成（防止拿到拷了一半的包）
- 关闭自动升级：config.json 设 `update.auto_upgrade: false`

> 命令行兜底仍是 `./scripts/upgrade.sh <包名>`（SSH 场景或应用起不来时）。

### 4.3 升级包分发（点对点交付）

发版：导出 → 微信/网盘 → 对方投放，三步。

**发布方（你）**：
1. 按 4.4「发布一个新版本」升版本号并在本机构建新版本
2. 运维页「升级包分发」→「一键导出升级包」（把当前运行版本打成 `aether-update-<版本>.tar.gz`，含镜像与 sha256 校验，约数分钟；变更说明自动随包）
3. 点「下载」拿到包文件，微信/网盘发给对方

**接收方（别人）**：
1. 把收到的 `aether-update-*.tar.gz` 放到服务器 `Aether/backups/` 目录（和备份文件同目录）
2. 等约 1 分钟，系统自动完成升级并删除安装包（见 4.2「升级包自动升级」）；版本相同/更低时用下方列表手动安装

安全说明：版本低于包内 `min_compatible` 会拒绝安装并提示；校验失败不影响当前运行。

### 4.4 发布一个新版本（发版流程，发布方操作）

版本号是升级机制的命门：**不升版本，接收方的自动升级永远不触发**（只升不降）。
每攒了一波改动要发布时，走一遍：

1. **升版本号**（仓库根目录，变更说明自动生成）：
   ```bash
   python scripts/new-version.py 1.1.0
   ```
   变更说明自动 = 上个发版以来的 git 提交记录（`git log --oneline`），
   也会打印出来供确认；想手写覆盖加 `--notes "..."`。
   版本号递增建议：修 bug 升末位（1.0.0→1.0.1）、加功能升中位（→1.1.0）、
   大改/不兼容升首位（→2.0.0，同时 `--min-compatible` 指定最低兼容版本）。
2. **提交并本机构建新版本**：
   ```bash
   git add version.json && git commit -m "chore(release): v1.1.0"
   docker compose up -d --build
   ```
3. **导出升级包**：运维页「升级包分发」→「一键导出升级包」
   （变更说明自动随包，无需再填）→ 得到 `aether-update-1.1.0.tar.gz`
4. **分发**：下载后微信/网盘发给接收方 → 对方放进 `Aether/backups/` 即自动升级

包是**整包**（含完整镜像，非增量），接收方装完即与你的 1.1.0 完全一致；
"变更说明"（git 提交记录）会随包展示在接收方的升级包列表里。

## 5. 备份与恢复

### 5.1 创建备份

点击「立即备份」，自动打包：

- `config.json`（应用配置）
- `.env`（API 密钥）
- HA 配置目录（排除运行时产物）
- MQTT 配置
- aether-data 数据卷

**保留策略**：最近 3 份，旧备份自动清理。

### 5.2 恢复备份

1. 选择备份文件
2. 点击「恢复」按钮（需二次确认）
3. 系统停止容器 → 恢复文件 → 重启服务

**注意**：恢复会覆盖当前数据，恢复前建议先导出诊断包备份。

## 6. 审计日志

显示最近 50 条运维操作记录，包括：

- 操作人
- 操作时间
- 操作类型（诊断、升级、备份等）
- 操作详情

**一键清空**：点击「一键清空」按钮（二次确认）可清空全部审计记录。清空动作本身会立即留下一条 `audit_clear` 记录（含操作人与清除条数），保证"谁清空了日志"可追溯。

日志存储位置：`logs/audit/ops_audit.jsonl`（JSONL 格式）

## 7. 数据出网模式

数据出网模式（云端对话/混合/纯内网）在**「高级」页（`/advanced`）的「数据出网模式」卡片**里切换，不在运维中心。聊天页会实时显示当前模式徽标（☁️/🔀/🏠）。三档模式与硬拦截规则详见《[数据流向说明](../tech/数据流向说明.md)》。

## 8. 常见问题

**Q：非管理员能看到运维中心吗？**

A：斜杠命令 `/operations` 对非管理员直接隐藏（菜单里不出现）；直接输网址访问能看到页面骨架，但所有操作返回 403。

**Q：升级失败怎么办？**

A：系统自动回滚到上一版本。如果回滚也失败，请手动恢复备份或联系技术支持。

**Q：诊断包包含敏感信息吗？**

A：密钥字段自动脱敏，但日志中可能包含设备名、IP 等。导出前请确认可分享。

**Q：备份存储在哪里？**

A：存储在宿主机 `backups/` 目录，以 `aether-backup-<时间戳>.tar.gz` 命名。
