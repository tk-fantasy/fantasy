# 系统健康检查指南

想让 Aether 稳稳跑着，偶尔「体检」一下很有必要。这篇讲怎么看系统状态、怎么快速定位问题。

## 一、总体健康检查

浏览器打开（需先登录）：

```
http://localhost:8010/api/health
```

返回字段：

| 字段 | 含义 |
|------|------|
| `status` | `ok` 表示服务在跑 |
| `llm_model` | 当前用的聊天模型 |
| `llm_enabled` | LLM 是否启用 |
| `llm_available` | LLM 是否真的能调通（启动时后台探一次） |
| `ha_available` | Home Assistant 是否连得上 |
| `camera` | 摄像头完整状态（见下） |
| `log_file` | 日志文件路径（`logs/app.log`） |

**`status: ok` + `llm_available: true` + `ha_available: true` = 一切正常。**

> 注意：这个接口要登录才能访问。想做无认证的健康探针（Docker/k8s），目前没有现成的。

## 二、组件状态检查

### 自动化规则在不在跑

```
http://localhost:8010/api/automation/status
```

返回：

| 字段 | 含义 |
|------|------|
| `status` | `not_started` 表示自动化没启动 |
| `automation.running` | 是否在运行 |
| `automation.silent_eval_enabled` | 静默评估开关（无运动时兜底评估） |
| `automation.silent_eval_interval_seconds` | 静默评估周期（后端启动默认 300 秒，`/advanced` 自动化 modal 可调） |
| `automation.default_cooldown_seconds` | 规则默认冷却 |
| `automation.motion_threshold` / `motion_threshold_max` | 运动检测阈值 / 上限（全局 `vision.motion_threshold`；多路每路阈值在 `cameras` 表） |
| `min_trigger_interval` | dhash 触发节流间隔（status 接口直接读 `vision.min_infer_interval_seconds`，默认 3s；单摄与多路路径都复用该配置） |
| `automation.camera_vl_display_enabled` | `/camera` 视觉展示推理开关（关掉只停预览，不影响自动化） |
| `automation.eval_count` | 累计评估次数 |

> 旧 `/api/agents/status` 仍保留兼容（只含 running/silent/eval_count 子集），建议用上面的新端点。这个接口**没有**调度器（scheduler）字段。定时任务的运行状态看 `/api/scheduled-tasks` 里每条任务的 `last_status`（`running`/`success`/`failed`/`interrupted`）。

### 摄像头状态

多摄像头化后每路摄像头一个状态入口，主摄像头（兼容）仍可用 `/api/state`：

```
http://localhost:8010/api/cameras        # 全部摄像头 + 各自状态
http://localhost:8010/api/cameras/{id}/state   # 指定一路
http://localhost:8010/api/state         # 兼容：主摄像头
```

关键字段（每路）：

| 字段 | 含义 |
|------|------|
| `camera_opened` | 摄像头有没有成功打开 |
| `frame_width` / `frame_height` | 画面分辨率 |
| `fps` / `worker_fps` | 抓帧 / 处理帧率 |
| `motion_distance` | 当前运动距离（超 `motion_threshold` 才触发推理，默认 -1 表示无参考帧） |
| `motion_threshold` | 运动阈值（per-camera 字段，默认 15） |
| `infer_count` | 累计推理次数 |
| `model_fps` | 推理频率上限 |
| `infer_busy` | 是否正在推理 |
| `feedback` | 当前识别反馈文本 |
| `last_error` | 最近一次错误 |

### 指标快照

```
http://localhost:8010/api/metrics
```

返回请求计数/延迟、工具调用次数、LLM 调用次数等，用于看负载情况。

## 三、排查速查表

按这个顺序过，大多数问题能定位：

| 步骤 | 检查什么 | 怎么做 | 正常应该是 |
|------|----------|--------|-----------|
| 1 | Docker 容器 | `docker compose ps` | 4 个容器（mosquitto / aether-ha / aether / aether-simulator）都 `Up` |
| 2 | 后端服务 | `http://localhost:8010/api/health` | `status: ok` |
| 3 | 前端页面 | `http://localhost:5173`（开发）或 `http://localhost:8010`（生产） | 显示登录页 |
| 4 | HA 连接 | health 里的 `ha_available` | `true` |
| 5 | LLM 可用 | health 里的 `llm_available` + `/models` 测试 | `true` |
| 6 | 摄像头 | `/api/cameras` 各路的 `camera_opened` 或 `/cameras` 面板 | `true`，有画面 |
| 7 | 自动化 | `/api/automation/status` 的 `running` | `true` |

哪步不对，从那步开始查。

## 四、Docker 服务状态

Aether 默认编排 **3 个**容器（simulator 默认不启动，首次启用 `docker compose --profile simulator up -d simulator`；另有可选 Ollama，见部署指南）：

| 服务 | 容器名 | 端口 | 作用 |
|------|--------|------|------|
| mqtt | `mosquitto` | 1884 | MQTT 消息代理 |
| homeassistant | `aether-ha` | 8123 | 智能家居平台 |
| aether | `aether` | 8010 / 8011 | 后端主服务 + 前端 SPA |
| simulator（可选） | `aether-simulator` | — | 虚拟设备模拟器（默认关闭，演示设备上报） |

```powershell
# 查状态
docker compose ps

# 看日志（最近 50 行）
docker compose logs homeassistant --tail 50
docker compose logs mqtt --tail 50
docker compose logs aether --tail 50
```

> HA 用官方镜像 `homeassistant/home-assistant:stable`（Docker Hub 同步版，国内拉取稳定），配置通过 `./ha_config` 挂载，compose 自动拉取，无需手动构建。

## 五、常见情况解读

### 摄像头没打开

- USB 没插好 / 被会议软件占用 / 笔记本物理开关关了
- `/cameras` 页检查该路「启用采集」和 `usb_index`，试 `0`/`1`/`2`；RTSP 源先点「试连」
- 看日志 `Get-Content logs\app.log | Select-String "camera"`

### 运动距离一直很高

- 画面里确实有动（风扇、窗帘飘）
- 静止时还高 → 摄像头噪点，调大 `motion_threshold`

### 视觉识别卡住

- LLM 太慢，系统有超时保护会自动恢复
- 经常发生 → 换快点的视觉模型，或调小 `downscale_max_side`

### `ha_available: false`

- HA 容器没跑：`docker compose ps homeassistant`
- HA 地址/Token 不对：检查 `config.json` 的 `ha` 段（或 `/advanced` 页 HA 配置段）
- **WLAN IP 变了**：DHCP 重分配后 HA 的 `internal_url`/`external_url` 会写死旧 IP，跑一遍 `./scripts/sync_ha_ip.sh` 自动更新并重启 HA 容器（配了计划任务则开机自动同步，见下面「HA IP 自动同步」一节）
- HA 还在启动中：等几十秒再查

### `llm_available: false`

- Key 没配或配错：`/models` 页面检查
- Key 失效/额度用完：去提供商后台看
- 网络不通模型 API

### 自动化 `eval_count` 不增长

- 自动化没启动（`running: false`）
- 看日志有没有 `automation` 相关报错

## 六、HA IP 自动同步

**问题**：DHCP 分配的 WLAN IP 会变（.26 → .47 → ...），但 HA 配置里写死了 IP，导致 OAuth 回调失败、xiaomi_home 授权接不进来。

**脚本**：`scripts/sync_ha_ip.sh`（bash，Windows 下用 Git Bash 跑）——检测当前 WLAN IP，与上次记录（`ha_config/.ha_ip_state`）对比，变了就自动：

1. 更新 `ha_config/configuration.yaml` 的 `internal_url` / `external_url`
2. 更新 `ha_config/.storage/core.config_entries` 的 xiaomi_home `oauth_redirect_url`
3. 重启 `aether-ha` 容器并等它就绪

```bash
./scripts/sync_ha_ip.sh           # 正常执行
./scripts/sync_ha_ip.sh --check   # 只检测不修改（dry-run）
```

**开机自启**：`scripts/install_sync_task.ps1` 装 Windows 计划任务（登录时自动跑一次）。

> 脚本只认私网地址（192.168./10./172.16-31.），Tailscale/公网 IP 会拒绝写入。手动跑完若 xiaomi_home 仍授权失败，需在 HA 界面「设置 → 设备与服务 → Xiaomi Home → 重新认证」走一次 OAuth。

## 七、测试入口

- **HA 连接测试**：`/advanced` 页面 HA 配置段的「测试」按钮
- **LLM Key 测试**：`/models` 页面每条 Key 的「测试」按钮
- **设备控制测试**：`/halist` 手动操作设备，看是否响应

## 八、小贴士

- 先看 `/api/health` 总体，再看具体组件
- 按速查表 1→7 过一遍，通常能快速定位
- 还是不行 → `logs/app.log` 找 `ERROR`/`Exception`
- 大部分疑难杂症重启后端能解决
- DEBUG 模式（`LOG_LEVEL=DEBUG`）能看工具调用和规则评估细节，排完记得改回 `INFO`
